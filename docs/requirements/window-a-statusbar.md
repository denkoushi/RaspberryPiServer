# Window A 要領書ステータスバー改修要件

## 1. 背景
- 2025-11-02 時点で DocumentViewer ステータスバーを追加し、`dv-barcode` 受信時に所在情報を提示できる状態になった。
- Pi4 実機での Playwright ライブテスト (`tests/e2e/window-a-live.spec.ts`) は成功したが、UI について以下の課題が残っている。
  - タブ切り替え時にボタン位置が揺れる（所在一覧・構内物流タブへ切り替えるとレイアウトが再配置される）。
  - ステータスバー要素がフォーカス移動しづらく、キーボード操作で即座に所在一覧タブへ遷移しにくい。
  - ステータスバー表示中も PDF ビューア領域をできるだけ広く確保する必要がある。

## 2. 改修方針
1. **レイアウト安定化**
   - ビュー切替ボタンブロックの高さを固定し、タブ表示中にボタン位置が上下しないよう CSS を調整する。
   - ステータスバーとタブの余白を統一し、所在一覧・構内物流タブへ切り替えた際にもレイアウトが崩れないことを確認する。
2. **アクセシビリティ**
   - ステータスバーのアクションボタン（所在一覧を開く）がタブ順に含まれるよう tabindex を明示し、Enter/Space で動作することを保証する。
   - スクリーンリーダー向けに ARIA ラベルを追加し、棚位置・デバイス・最終更新時刻が読み上げられるようにする。
3. **ビューアとの共存**
   - ステータスバーの高さを 40px 前後に抑え、iframe 表示領域が狭くならないようにする。
   - ウィンドウ幅が狭い場合はレスポンシブに折り返し、主要情報（棚位置・デバイス・最終更新）が 2 行以内に収まるようにする。

## 3. 受入れ基準
- Pi4 実機でタブ切り替えを繰り返してもビュー切替ボタンの位置がズレない。
- キーボードのみで「所在一覧を開く」操作が可能で、押下後に所在一覧タブへ切り替わる。
- `PLAYWRIGHT_ENV_FILE=.env.test npx playwright test tests/e2e/window-a-live.spec.ts --config=tests/e2e/playwright.config.ts` が PASS を継続する。
- DocumentViewer の PDF 表示領域が従来と比較して実質的に狭くならない（開発者ツールから高さを計測し、差分 < 10px を目安とする）。
